# GAP ANALYSIS: Multi-Agent AI Security Operations Center (SOC)

**Document Version:** 1.0.0  
**Audit Reference:** `PROJECT_AUDIT.md`  
**Framework Priorities:**  
- **P0**: Critical functionality or data-integrity failure  
- **P1**: Core SOC workflow incomplete or misaligned with directive  
- **P2**: Dashboard and usability improvements (removing misleading mock data)  
- **P3**: Advanced features, optimization, and documentation  

---

## Gap Analysis Matrix

| Requirement | Existing Implementation | Problem | Required Change | Priority |
|---|---|---|---|---|
| **P0-1: 2-VM Perimeter IP Blocking** | `backend/app/services/response_service.py` lines 136–142 checks `VMNode.role == 'GATEWAY'`. | In the 2-VM architecture (Attacker + Victim), there is no third VM acting as a Gateway. Executing `BLOCK_IP` raises HTTP 409 Conflict. | Modify `execute_response_action` to allow executing `BLOCK_IP` directly on the monitored `ENDPOINT` VM (Victim VM) via `iptables -I INPUT -s <ip> -j DROP`, or automatically route gateway actions through the primary endpoint in a 2-VM topology. | **P0** |
| **P0-2: Eliminate Mock Fallbacks in Incident Mapping** | `soc-frontend/src/api/incidentMapper.js` defaults missing fields to mock constants (`198.51.100.23`, `Sarah Chen`, fake timeline `10:42:31`). | Because backend model `Incident` uses `affected_ips`, `title`, and `ai_summary` while the mapper looks for `source_ip`, `threat_name`, and `agent_analysis`, the mock fallbacks always trigger, displaying fake data on the UI. | Align `incidentMapper.js` directly with `IncidentResponse` schema (`affected_ips[0]`, `title`, `ai_summary`, real `IncidentEvent` chronology). Remove all hardcoded IP, analyst, and timeline fallbacks. | **P0** |
| **P0-3: Eliminate Fabricated Incident IDs in Live Event Stream** | `soc-frontend/src/hooks/useLiveEvents.js` line 38 assigns `correlationId: 'INC-2026-001'` to any HIGH/CRITICAL event without an incident. | Artificially marks un-correlated single events as belonging to an incident, violating the fundamental SOC correlation rule. | Remove `(e.severity === 'CRITICAL' \|\| e.severity === 'HIGH' ? 'INC-2026-001' : null)`. Only display `correlation_id` when populated by the backend. | **P0** |
| **P1-1: Correlated Event Count vs Incident Count** | `soc-frontend/src/pages/Dashboard.jsx` lines 61–63 sets `correlatedCount = totalIncidents`. | Conflates incident count with the count of correlated security events. | Compute `correlatedEvents` by summing unique contributing events across correlated incidents (`sum(inc.event_count)` or count of distinct `IncidentEvent` records). | **P1** |
| **P1-2: Orchestrator Duplicate Result Append Bug** | `backend/app/agents/orchestrator.py` lines 302–303 appends `corr_res` twice to `agent_results`. | Results list contains a duplicate entry for the Correlation Agent on every execution run. | Remove redundant second `agent_results.append(corr_res)`. | **P1** |
| **P1-3: Fallback to Mock Data on Empty Incident List** | `soc-frontend/src/pages/Incidents.jsx` and `AiAnalysis.jsx` import `defaultIncidents` from `mockSecurityData.js`. | If backend has 0 incidents or returns an error, the UI displays 3 fake pre-baked incidents rather than an authentic empty state. | Remove fallback to `defaultIncidents`. Render clean empty state (`No correlated incidents recorded yet`) and real error alerts. | **P1** |
| **P1-4: Reverse Tunnel Supervisor & Auto-Reconnect** | `scripts/start_vm_tunnels.ps1` runs interactive SSH jobs with no automatic health monitoring or systemd service on Windows host. | Host reboot, network jitter, or cloud VM SSH timeout drops the reverse tunnel, silently breaking guest telemetry ingestion. | Create a persistent supervisor PowerShell script/task that monitors port 18000 on both VMs and automatically re-establishes dropped tunnels. | **P1** |
| **P2-1: Remove Stale VirtualBox Server Node** | Database `vm_nodes` table contains `vm-server-01` (`192.168.56.15`), and `DEFAULT_LAB_NODES` seeds it. | Displayed as CONFIGURED with no telemetry, confusing users expecting a strict 2-VM topology. | Keep `vm-server-01` scoped only to mock/unit tests (`test_virtual_lab.py`), or mark its role explicitly as optional/offline so the UI accurately displays `2 / 2 Active`. | **P2** |
| **P2-2: Replace Hardcoded Dashboard Mini-Sparklines** | `soc-frontend/src/pages/Dashboard.jsx` line 4 imports `miniSparklines` from `mockSecurityData`. | Displays static, non-functional activity graphs on top KPI metric cards. | Derive sparkline data points from the actual `event_trends` array returned by `api.getDashboardSummary()`. | **P2** |
| **P2-3: Real-Time Incident Status Refresh in Correlation View** | `soc-frontend/src/pages/Correlation.jsx` polls every 10s, but does not subscribe to WebSocket `INCIDENT_CREATED` / `INCIDENT_UPDATED`. | Analyst must wait up to 10 seconds to see new incident correlation clusters appear. | Add WebSocket listener for `INCIDENT_CREATED` and `INCIDENT_UPDATED` in `Correlation.jsx` to update state immediately. | **P2** |
| **P3-1: Auditd Process Tree Streaming from Guest** | `vm_telemetry_collector.py` parses `auth.log` and `nginx/access.log`, but does not stream kernel `auditd` syscall events. | Process parent/child tree lineage in `EndpointAgent` relies on regex heuristics rather than true auditd PPID chains. | Add optional auditd log parser (`/var/log/audit/audit.log`) in `vm_telemetry_collector.py` to capture `EXECVE` syscalls with PID, PPID, and exe. | **P3** |
| **P3-2: Supervised ML Flow Feature Alignment** | `dataset_pipeline.py` extracts flow features from raw packets, but live `vm_telemetry_collector.py` sends high-level connection events. | Supervised UNSW-NB15 Random Forest is evaluated on synthesized features rather than full bidirectional flow statistics. | Standardize flow feature generation on the Victim VM to stream lightweight flow windows into `/api/events`. | **P3** |
